# Existing GitHub import: failure preservation

The existing owner import request and JSON success shape are unchanged. Import validates the requested repository/root, captures a server content revision before fetching, and stages accepted source files separately. Source validation/copy/model-save failure retains the previous workspace. A changed disk revision returns409 without replacing those edits. The controller's full import replaces the source only after staging; existing remote pull/overlay callers retain unrelated files on success. A subtree failure returns its error; it no longer retries silently as a ZIP import.

Promotion uses the existing project write lock and a sibling stage/backup directory. Metadata is saved in a control DB transaction; handled failures restore the previous directory. This provides failure preservation for the tested request paths, not a filesystem crash journal or a guarantee of uninterrupted reads during the directory swap. Overlay mode snapshots/copies the existing workspace; large-workspace resource limits still need acceptance.

`tests/regressions/github-import-preservation.php` covers25 local checks, including invalid later files, tree/map limits, stale content, metadata failure, source replacement/overlay, foreign project preservation, stage cleanup, real controller validation/admission finalization and an actual loopback connection refusal without ZIP fallback. No GitHub credentials or external service is used; connection refusal is real HTTP-client behavior rather than an HTTP fake. Commerce's Postman simulation is unchanged.

GitHub ZIP extraction also validates paths/types/header names/collisions before streamed extraction. Fixed ceilings:25MiB compressed,2500files,2MiB/file,100MiB expanded,depth32,ratio100; lower configured limits apply. Actual output bytes are bounded as they are decoded. Windows aliases/encoded traversal/backslashes/links/git hooks/ambiguous case and file-directory paths are rejected. Raw local/central filenames are checked because libzip truncated a crafted NUL name in the regression. Unsupported multi-disk/ZIP64 directory formats fail explicitly. `github-archive-safety.php` passes24 local checks; ordinary source/LICENSE/NOTICE are preserved without execution.

These are repairs in G2, not completion of G1–G3. Pinned inspection, partial/truncated-tree and blob completeness, license/secret/reviewed lockfile handling, reviewed source diff/expected revision in the UI, job/provenance records, dirty editor buffers, lease fencing, isolated resource limits and final independent review remain required. Source import never grants permission to run imported scripts on the host. Import source status does not certify a build or publication.
