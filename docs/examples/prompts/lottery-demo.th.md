# Prompt ตัวอย่าง: เว็บหวยรัฐบาลแบบเดโม

คัดลอกข้อความในกรอบด้านล่างไปวางใน Lab ได้ ตัวอย่างนี้เป็นข้อกำหนดสำหรับสร้างเว็บ ยังไม่ได้สร้างหรือเปิดใช้ระบบรับรายการหรือชำระเงินจริง

```text
สร้างเว็บเดโมภาษาไทยชื่อ “เลขดี Demo” สำหรับจำลองการกรอกเลขหวยรัฐบาล 2 ตัวและ 3 ตัว ตั้งแต่สมัครสมาชิก ส่งรายการ ตรวจผล จนถึงหลังบ้านยืนยันรับชำระและจ่ายรางวัล ใช้ข้อมูลและยอดเงินสมมติทั้งหมด

ออกแบบให้ใช้งานบนมือถือสะดวก ใช้สีกรมท่า ครีม และเขียว ตัวเลขอ่านง่าย ปุ่มกดใหญ่ มีสถานะกำลังโหลด ไม่มีข้อมูล ผิดพลาด และสำเร็จอย่างชัดเจน แสดงป้าย “ระบบเดโม • ยอดเงินสมมติ” บนทุกหน้าที่เกี่ยวกับเงิน

หน้าที่ต้องมี
1. หน้าแรก: แสดงงวดปัจจุบัน วันและเวลาปิดรับ สถานะเปิด/ปิดรับ ผลงวดก่อน ข่าวสาร และปุ่ม “สมัครสมาชิก” “เข้าสู่ระบบ” “กรอกเลข”
2. สมัครสมาชิก/เข้าสู่ระบบ: ชื่อที่แสดง อีเมล รหัสผ่าน และยืนยันรหัสผ่าน ตรวจสอบข้อมูล เก็บรหัสผ่านอย่างปลอดภัย เข้าสู่ระบบแล้วกลับไปหน้าที่ตั้งใจเปิด
3. หน้ากรอกเลข: เลือก 2 ตัวบน, 2 ตัวล่าง, 3 ตัวตรง หรือ 3 ตัวโต๊ด กรอกเลขและจำนวนเงินต่อรายการ เพิ่มหลายรายการได้ มีแป้นตัวเลขและสรุปด้านข้าง
4. หน้ารายการ: แก้จำนวนเงิน ลบรายการ แสดงประเภทรายการ เลขที่เลือก ยอดต่อรายการ อัตราจ่าย และรางวัลที่อาจได้รับ แยกยอดชำระรวมออกจากรางวัลที่อาจได้รับ
5. หน้าชำระเงินเดโม: แสดงเลขอ้างอิงและยอดสมมติ แนบหลักฐานทดสอบ กด “ส่งหลักฐาน” แล้วเห็นสถานะ “รอตรวจสอบ” การแนบหลักฐานไม่ทำให้รายการได้รับอนุมัติทันที
6. หน้าประวัติสมาชิก: ดูรายละเอียดรายการ สถานะชำระเงิน ผลถูก/ไม่ถูก รางวัล และสถานะคำขอรับรางวัล แสดงเฉพาะข้อมูลของสมาชิกที่เข้าสู่ระบบ
7. หน้าผลรางวัล: เลือกงวด ดูผลที่หลังบ้านประกาศ และดูรายการของตนที่ถูกรางวัล
8. หน้าข่าวสารและติดต่อ: ข่าวจากฐานข้อมูล และฟอร์มชื่อ อีเมล หัวข้อ ข้อความ ส่งแล้วมีเลขอ้างอิงให้ติดตาม
9. หลังบ้าน: สรุปยอดตามงวด จัดการข่าวและข้อความติดต่อ เปิด/ปิดงวด ตั้งอัตราจ่าย ตรวจหลักฐานรับชำระ กรอกผล และตรวจคำขอจ่ายรางวัล

กติกาเดโมและการคำนวณ
- เก็บเลขเป็นข้อความเสมอ เพื่อให้ 00, 07 และ 007 คงเลขศูนย์ด้านหน้า รับเฉพาะเลข 0–9 และจำนวนหลักที่ตรงกับประเภท
- ใช้ผล “3 ตัวบน” และ “2 ตัวล่าง” ที่ผู้ดูแลกรอกเองในแต่ละงวด โดยผล 2 ตัวบนคือสองหลักท้ายของผล 3 ตัวบน แสดงว่าเป็นผลทดสอบที่ผู้ดูแลบันทึก
- 2 ตัวบน/ล่าง และ 3 ตัวตรง ต้องตรงทุกหลักตามลำดับ ส่วน 3 ตัวโต๊ดต้องมีเลขและจำนวนเลขซ้ำตรงกันโดยไม่สนลำดับ เช่น 112 ตรงกับ 121 แต่ไม่ตรงกับ 122
- ตั้งอัตราจ่ายสมมติเริ่มต้น: 2 ตัวบน/ล่าง 90 เท่า, 3 ตัวตรง 900 เท่า, 3 ตัวโต๊ด 150 เท่า ผู้ดูแลเปลี่ยนได้ก่อนเปิดงวด อัตรานี้เป็นค่าทดลอง ไม่ใช่อัตราจ่ายที่ประกาศโดยรัฐบาล
- รับยอดจำนวนเต็มตั้งแต่ 1 ถึง 1,000 บาทสมมติต่อรายการ เก็บการคำนวณเงินเป็นหน่วยสตางค์จำนวนเต็ม
- รางวัลเมื่อถูก = ยอดต่อรายการ × อัตราจ่าย โดยยอดรางวัลนี้รวมเงินต้นแล้ว ไม่บวกเงินต้นซ้ำ ถ้าไม่ถูกให้เป็น 0
- ตัวอย่าง: เลข 07 แบบ 2 ตัวล่าง จำนวน 20 บาท ที่อัตรา 90 เท่า จะแสดงรางวัลเมื่อถูก 1,800 บาท และกำไรสุทธิ 1,780 บาท
- แสดงรางวัลแยกต่อรายการและรวมเฉพาะรายการที่ถูกจริงหลังประกาศผล ห้ามบวกรางวัลที่อาจได้รับของเลขที่ไม่สามารถถูกพร้อมกันแล้วเรียกว่าเป็นรางวัลรับประกัน
- บันทึกอัตราจ่ายไว้กับรายการตอนยืนยัน เพื่อไม่ให้การเปลี่ยนอัตราภายหลังเปลี่ยนรายการเดิม
- ใช้เวลาฝั่งเซิร์ฟเวอร์ตัดสินการปิดรับ แสดงเวลา Asia/Bangkok ห้ามรับหรือแก้รายการหลังปิดรับ
- หลักฐานรับชำระต้องได้รับอนุมัติก่อนปิดรับจึงจะมีสิทธิ์รับรางวัลในเดโม รายการที่ยังรอตรวจหลังปิดรับให้หมดสิทธิ์ และห้ามผู้ดูแลอนุมัติย้อนหลังให้มีสิทธิ์หลังเห็นผล

Flow รับชำระและจ่ายรางวัล
- สมาชิกยืนยันรายการ → รอชำระ → ส่งหลักฐานทดสอบ → รอตรวจสอบ → ผู้ดูแลยืนยันรับชำระ หรือปฏิเสธพร้อมเหตุผล
- หากปฏิเสธ สมาชิกส่งหลักฐานใหม่ได้ก่อนเวลาปิดรับ โดยเก็บประวัติการตรวจแต่ละครั้ง
- ผู้ดูแลปิดงวด กรอกผล ดูตัวอย่างผลคำนวณ แล้วกดยืนยันประกาศผล ระบบคำนวณรายการที่มีสิทธิ์จากฐานข้อมูล และป้องกันการประกาศซ้ำ
- สมาชิกที่ถูกมีปุ่ม “ขอรับรางวัล” พร้อมข้อมูลช่องทางรับเงินสมมติ ส่งแล้วเป็นสถานะรอตรวจสอบ
- ผู้ดูแลตรวจรายการที่ถูกและคำขอ จากนั้นกด “อนุมัติจ่าย” และ “ยืนยันจ่ายแล้ว” เป็นคนละขั้นตอน ขั้นสุดท้ายต้องมีเลขอ้างอิงและหลักฐานทดสอบก่อนเปลี่ยนเป็นจ่ายแล้ว
- การกดอนุมัติหรือยืนยันในเดโมเป็นการบันทึกสถานะ ไม่มีการโอนเงินจริง
- ป้องกันกดซ้ำ รีเฟรชซ้ำ และผู้ดูแลสองคนยืนยันพร้อมกัน ไม่ให้เกิดรายการหรือรางวัลซ้ำ เก็บผู้ดำเนินการ เวลา และเหตุผลของการเปลี่ยนสถานะ

ฐานข้อมูลและสิทธิ์
- บันทึกสมาชิก งวด ประเภทและอัตราจ่าย รายการและบรรทัดเลข ประวัติหลักฐานชำระ ผลรางวัล คำขอรับรางวัล ประวัติการจ่าย ข่าวสาร และข้อความติดต่อในฐานข้อมูลจริงที่เชื่อมต่อกับโปรเจกต์นี้
- ตรวจข้อมูล คำนวณยอด ตรวจเวลา และเปลี่ยนสถานะที่ฝั่งเซิร์ฟเวอร์เสมอ ห้ามเชื่อจำนวนเงิน ผลถูกรางวัล หรือสิทธิ์ผู้ดูแลที่ส่งมาจากหน้าเว็บ
- สมาชิกอ่านและส่งรายการของตัวเองเท่านั้น หลังบ้านต้องตรวจสิทธิ์ผู้ดูแลทุกครั้ง หลักฐานและข้อมูลรับเงินเก็บแบบ private และเปิดดูได้ตามสิทธิ์
- ห้ามใส่ service key หรือข้อมูลลับใน frontend ห้ามใช้ localStorage เป็นฐานข้อมูลสมาชิก รายการ หรือหลักฐาน ห้ามแสดงว่าส่งสำเร็จถ้ายังไม่ได้บันทึกจริง
- ใช้ฐานข้อมูลที่โปรเจกต์เชื่อมต่อไว้ หากยังไม่มี schema หรือระบบรองรับ ให้แสดงรายการที่ต้องติดตั้งและจัดทำข้อเสนอ migration ให้เจ้าของตรวจแล้ว Apply ผ่าน flow ของแพลตฟอร์มก่อน ห้ามรัน SQL หรือเปิดใช้การชำระเงินจริงโดยอัตโนมัติ
- หากสภาพแวดล้อมรองรับเฉพาะ frontend ให้ทำหน้าจอเดโมพร้อมข้อมูลทดสอบและระบุส่วนที่ยังไม่เชื่อมต่ออย่างตรงไปตรงมา ห้ามอ้างว่า flow ฐานข้อมูลหรือการชำระเงินเสร็จแล้ว

เกณฑ์ตรวจรับ
- สมัคร → เข้าสู่ระบบ → ใส่ 07 และ 007 → เพิ่ม/แก้/ลบ → ยืนยันรายการ → ส่งหลักฐาน → หลังบ้านอนุมัติ → ปิดงวด → ประกาศผล → ขอรับรางวัล → ยืนยันจ่าย → รีเฟรชแล้วข้อมูลยังอยู่
- ทดสอบ 2 ตัวบน/ล่าง, 3 ตัวตรง, โต๊ดเลขไม่ซ้ำและเลขซ้ำ รวมทั้งรายการที่ไม่ถูก
- ทดสอบยอดไม่ถูกต้อง เลขหลักไม่ครบ ปิดรับแล้ว หลักฐานถูกปฏิเสธ กดซ้ำ และเข้าถึงรายการของสมาชิกคนอื่น
- ทดสอบคำนวณจากฝั่งเซิร์ฟเวอร์ การยืนยันจ่ายพร้อมกัน และการเปลี่ยนอัตราจ่ายโดยไม่กระทบรายการเดิม
- Build จริง ตรวจหน้ามือถือและเดสก์ท็อป และรายงานว่าอะไรทดสอบผ่าน อะไรยังติดข้อจำกัด ห้ามสรุปว่าครบ flow จากภาพหน้าจออย่างเดียว
```
