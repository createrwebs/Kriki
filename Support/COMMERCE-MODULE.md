# Managed storefront and manual PromptPay

Status2026-10-25: **implemented local flow, production readiness closed**. The global `lab-modules.business_writes_enabled` flag remains false. Installation `ready` means schema installation was verified; it does not certify the whole commerce flow.

## Current behavior

The owner desk manages products, recipient settings, news, contact messages, orders and payment reviews. Code-owned widgets embed in existing trusted generated pages; a production build retains actual JSX and CSS. Business data uses the account's original pinned Supabase ref with project/module predicates, never the platform control database.

Orders v2 provides a ten-minute server quote. Customers review and explicitly confirm its item/amount snapshot. PostgreSQL locks and rechecks product/payment versions; changed price, availability, recipient or expired quote returns409 without creating an order. One quote can be consumed by one creation key. Exact accepted retries recover immutable snapshots even after expiry/disable; the widget freezes an ambiguous creation payload and retries the same key. Guest header capability expires24 hours after creation and can be explicitly revoked by the owner. Only product IDs/quantities and session-scoped order access are persisted in browser storage. Owner history remains after disable/downgrade/freeze while the original datastore is connected.

Manual-payments v2 stores normalized new PNG images in a verified private bucket, with metadata-only attempt/list responses. A durable upload lease and atomic commit separate Storage from PostgreSQL safely. Failed uncommitted objects are claimed before deletion; ambiguous committed responses recover evidence. Bounded owner reconciliation recovers expired receipts and retains immutable tombstones for delayed workers. Explicit owner viewing issues an exact pinned five-minute URL after fresh ownership/privacy checks. Historical inline evidence now has an explicit owner-session PNG viewer with fresh scope checks on every fetch and five-minute UI clearing. It preserves original bytes in the database and proof hashes/reviews; there is no automatic migration or retention deletion.

A decoded/re-encoded slip is submitted for review. It does not mean payment was received. Owner acceptance requires the bank acknowledgement checkbox and server `bank_verified:true`; a bank API is not integrated. The owner must independently check amount, recipient and actual credited transaction. PostgreSQL locks/CAS prevent contradictory reviews and resetting a paid order. Rejected evidence is retained; a new submission is a separate attempt. No refunds, legal receipts, tax invoices or booking deposits are implemented by this module.

Current interfaces: [OpenAPI](../docs/api/commerce.openapi.yaml), [managed control/data contract](../docs/contracts/managed-modules.md), [local generated Postman requests](../postman/collections/managed-commerce-implemented/README.md).
